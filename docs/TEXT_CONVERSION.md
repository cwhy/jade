# Text conversion and retained source boundaries

Alpha.22 is an experimental engine checkpoint. It adds Body/code conversion,
source-preserving joins across original containers, and text selection across
those visible groups. Application menus and full product qualification are
separate from these engine contracts.

## Ownership and representation

A visible paragraph or code block may refer to several original text sources.
Conversion owns presentation and boundary membership; it does not replace the
sources, take ownership of a peer's text, or copy whole paragraphs. An optional
origin descriptor associates each source window with its original list or direct
container. Original list conversions retain numbering and whole-item ownership.

A display join hides a separator across compatible adjacent sources. It keeps its
own Undo contribution. Undoing conversion can therefore leave a joined Body
paragraph; undoing the separator deletion restores the original visible boundary.
Offline Enter and text remain attached to their original sources. Explicit scoped
styles can require a boundary while the join contribution remains recorded.

Source retirement is independent of presentation. Clearing a cell or deleting its
table retires source nodes and hides dependent presentation. Undo restores the
same identities and anchors. Destructive reviews include presentation witnesses,
so a concurrent conversion invalidates an outdated review.

## Public concepts

- `@cwhy/jade-core/conversion` exposes preview and plan functions. Preview is inert;
  formatting loss requires explicit confirmation through the plan's options.
- `@cwhy/jade-core/document-read` provides the effective document, including text,
  group boundaries, offsets and gap mapping. Consumers must use this reader for
  displayed content; raw storage nodes are not the rendered document.
- The browser controller exposes conversion review/commit operations and uses the
  same source-aware selection, keyboard and renderer paths.
- One canonical authority admits the command. The existing Client, Room, receipt
  replay and owned Undo mechanisms remain the collaboration boundary.

Adjacent Body selections in one document or cell can span separate or joined
retained sources. Replacement retains the authored start/end gaps and uses the
existing replacement-origin ledger. Interior peer typing follows the restored
selection on Undo; outside typing remains on its original side. Redo restores the
peer's original position in the replacement. The inserted run belongs to the end
source, avoiding a separate cross-source relocation operation during Undo.

Native code preserved between converted sections retains its own boundary and
language. It need not own a conversion record: admission checks its actual
projected container membership. Images delimit text sections and are not flattened
into code text. Remembered languages survive explicit round trips; conflicting
remembered languages yield Plain text. See the contract tests for exact scope and
concurrent ownership rules.

## Storage and compatibility

Alpha.22 uses codec54 and wire60. Existing codec52 application checkpoints are
read through the explicit validated load boundary; their text identities,
receipts, operation payloads and stored Undo ownership remain intact. Wire58 local
journals are rewritten atomically before connecting, preserving pending operation
bytes. A failed local write leaves the original journal available and does not
connect. Live peers must use wire60. The isolated codec53 experiment is not an
application migration source.

A synthetic fixture generated by actual alpha.21 installed packages exercises
checkpoint loading, pending replay, lost acknowledgements, duplicate decisions,
anchors and owned Undo. This is stronger than changing a new record's codec label
and assuming it represents an older schema. Session-local Undo across reopening
is not newly promised by these load checks.

## Qualification and remaining limits

The source/boundary candidate passed 4,528 packaged contracts, 40 internal checks
and 132 headless Chromium flows before promotion. Compatibility tests are added
for the canonical package. Counts for the final package are recorded in STATUS.

Arbitrary source reparenting, richer mixed-object cross-block selections,
long-session/five-editor workloads and native platform qualification remain open.
Tests of a bounded model sequence do not establish production readiness or a
browser/network latency distribution. No npm registry publication is implied.
