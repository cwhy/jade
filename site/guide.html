A small guide to jade.

The editing engine is one part of your document application. Here is what it does, and where your application takes over.

Start with the playground

The playground has two independent Jade clients and a shared in-memory authority. Type in either editor and the other receives the accepted changes. Nothing you type is sent to a server.

  1. Add a sentence in Editor A, then add a different sentence in Editor B.
  2. Press Undo in Editor A. It undoes A’s contribution while preserving B’s.
  3. Disconnect Editor B. Keep writing on both sides, then reconnect B to reconcile their edits.
  4. Edit the list or code block inside a table cell. These are structured document nodes.

Use Enter and Backspace for paragraphs and lists, Tab and Shift+Tab to indent list items, and your platform’s Undo/Redo shortcuts. The toolbar also provides Undo and Redo. Some engine features have no control in this deliberately small demo.

The demo is temporary: reload or Reset sample starts over. It has no sign-in, shared room link, persistent journal, upload service or remote cursors. It demonstrates collaboration semantics in one browser tab, not real network latency. Desktop Chrome is the current editing target; native input and wider browser support are still being qualified.

A document, not a Markdown string

Jade represents documents as structured nodes with stable identities. Tables contain cells; cells can contain paragraphs, lists, code blocks and image references. Text positions and editing operations refer to the document model.

Undo belongs to the actor who made the change. It is not a replacement of the whole document with an older snapshot. Collaborators’ contributions are handled through the engine’s operation and identity rules.

Images reference assets managed by your application. Jade does not upload files or decide who can download them.

Choose the pieces you need

  • @cwhy/jade-core — document structure, editing commands, selections, anchors and owned Undo.
  • @cwhy/jade-browser — DOM rendering, browser input, composition, selection and clipboard adapters.
  • @cwhy/jade-collaboration — clients, authority decisions, replay and session orchestration through host-provided ports.
  • @cwhy/jade-protocol — wire version and operation envelope validation.
  • @cwhy/jade-testkit — synthetic fixtures and helpers for tests.

Your app supplies authentication, authorization, transport, durable storage, asset handling and the interface around the editor. The playground’s local authority is a demonstration host, not an authorization boundary or a production server.

Use the documented package exports. See the architecture document for boundaries and the playground source for a small browser integration.

Run it locally

You need Node.js 22.13 or newer and npm. The coordinated packages are in the repository; they are not published to npm.

git clone https://github.com/cwhy/jade.git
cd jade
npm test
npm run site:build
npm run site:serve

Open localhost:4173. To create package tarballs for your own application, run npm run pack:local and follow the repository instructions.

Early software, built in the open

Jade is alpha software. APIs and document formats may change. The regression suite covers a bounded set of editing and collaboration contracts; it is not a production certification. Read the current status and limitations before choosing it for a project.
